# Participation Model

## Open Source Participation Roles

| Role | Contribution | Expected Commitment |
|------|--------------|---------------------|
| Public Reviewer | Comment on a company workspace, issue, or schema | One-off |
| Domain Contributor | Correct workflows, terminology, or evidence requirements | Occasional |
| Technical Contributor | Submit fixtures, schemas, mappings, tests, or code | Contribution-based |
| Design Advisor | Participate in recurring design reviews for a product category | Light recurring |
| Working Group Maintainer | Help organize issues, decisions, releases, and reviews | Ongoing |
| Observer | Follow discussions without public contribution | None |

## Contribution Pathways

### Low Effort
- Correct one sentence
- Answer one open question
- Flag an invalid assumption
- Recommend a domain term
- Identify a missing evidence record

### Medium Effort
- Review an event contract
- Review artifact limitations
- Provide a synthetic field dictionary
- Contribute a redacted export shape
- Participate in one open review session

### Higher Effort
- Submit schema changes
- Add fixtures or conformance tests
- Build an adapter
- Maintain a product-category profile
- Co-author an open technical note

## Governance
The board operates through GitHub issues and pull requests. Maintainers accept, revise, defer, or reject decisions based on community feedback. No formal corporate authority is implied.

## Public Information Notice
All company workspaces are based on public information and are explicitly presented as unverified design hypotheses. Companies may request corrections, attribution changes, or removal of inaccurate representations at any time.
