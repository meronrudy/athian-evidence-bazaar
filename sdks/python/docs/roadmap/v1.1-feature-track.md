# Agevidence Python SDK v1.1 Feature Track

This is the first post-v1 feature track. It must preserve the v1 primitive and
provenance fields unless a future major version is intentionally planned.

## Parent Task 1: Provenance Policy Improvements

- [ ] Improve scoring explanations while preserving `ProvenanceReport` fields.
- [ ] Add configurable finding severity policy without changing default v1 behavior.
- [ ] Add more remediation examples for source records, instruments, calibration, model runs, and intervention batches.
- [ ] Keep local checks separate from eligibility, issuance, verification, claim ownership, and institutional reliance.

## Parent Task 2: Source Adapter Ecosystem

- [ ] Add more source-adapter examples and synthetic fixture packs.
- [ ] Add adapter packaging guidance to the public docs.
- [ ] Add a third-party adapter checklist for CI and fixture coverage.
- [ ] Add an optional template package once two external adapters follow the same shape.

## Parent Task 3: Compatibility Manifest

- [ ] Keep `reference/compatibility-manifest.json` synchronized with public docs.
- [ ] Add release-readiness checks for manifest version and required sections.
- [ ] Decide whether the manifest should be packaged in the wheel in v1.1.
- [ ] Document machine-readable compatibility in release notes.

## Parent Task 4: Hosted Client Examples

- [ ] Add hosted client examples for projects, source records, model runs, artifact metadata, and country/profile workflows.
- [ ] Keep hosted examples after local-first docs.
- [ ] Ensure hosted examples do not imply local SDK checks establish institutional reliance.

## Parent Task 5: Documentation Publishing

- [ ] Decide whether Markdown docs remain repository-native or move to a static docs site.
- [ ] If a static site is selected, add docs build config in a separate PR.
- [ ] Add link checking in CI before publishing docs.
- [ ] Keep PyPI README short and local-first.
